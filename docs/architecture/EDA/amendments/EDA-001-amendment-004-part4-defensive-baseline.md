# EDA-001 Amendment 004 — Part 4 Defensive Baseline Reconciliation

**Parent:** EDA-001 — Enterprise Data Architecture  
**Status:** Applied / Reconciled  
**Date:** 2026-08-22

## Decision

EDA-001 shall explicitly recognise **EDA-001 Part 4 — Platform Protection, Resilience & Defensive Engineering** as an established defensive constraint on enterprise data, service, integration, AI, operational and implementation architecture.

Part 4 does not replace EDA-001. It constrains subsequent architecture wherever security, resilience, abuse prevention, assurance, privacy, IP protection or defensive operation is material.

## Precedence

EDA-001 defines enterprise architecture structure and data responsibilities.

EDA-001 Part 4 defines the defensive requirements that those structures must satisfy.

ADRs define architectural decisions and rationale.

EIPs define reusable implementation/integration patterns.

## Reconciled Part 4 Dependencies

Future EDA, ADR and EIP documents must account for the completed Part 4 baseline, including API defence, trust, authenticity, monitoring, containment, incident response, resilience, adversarial verification, IP protection, defensive scalability, governance and assurance.

## Closure

This amendment resolves GAP-001 from ARCH-GAP-001. No reversal of EDA-001 is required.
